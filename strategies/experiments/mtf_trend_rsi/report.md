## 跟原始研究的落差：mom_1D_10 的「顯著」很可能是未修正的前視偏誤

原始研究宣稱 `mom_1D_10` 顯著（Holm 校正後 p=0.0007）。
本報告的 D1 gate 合併沿用 `trendpullback/utils.py` 修過的 `shift(1)` no-lookahead 寫法（D1 bar 自己
的值要到收盤才完整已知，backward merge 前必須位移一格，否則當天的 gate 會洩漏給當天自己的 H1
bar）——`trendpullback` 自己就是先踩到這個 bug 才修的（見其 report.md 「0. 先修 bug」）。原始
`mtf_trend_rsi` 用的是另一個專案的 `utils/factors.py::add_daily_trend_filter`，**沒有查證過那個函式
是否做了同樣的位移**。本報告修正後重新檢定，`mom_1D_10` 在三個樣本都不顯著（見下）——這跟原始結論
方向相反，而「同一個因子、換一個沒有前視偏誤的實作就從顯著變不顯著」本身就是一個值得記錄的訊號,不能
排除原始「顯著」結果部分來自未修正的前視偏誤。

跟 `trendpullback` M5 版本的唯一顯著格（OOS/with_gate, hit rate=0.383，方向相反）是同一種模式：
**這個 repo 目前測過的兩個家族，唯一出現「通過 Holm 校正」的格子都是反方向顯著**，不是找到可用邊際。

## 結論

1. **`mom_1D_10` 在修正 D1 gate 的前視偏誤後不再顯著**（三個樣本 Holm p=1.0000）——跟原始研究宣稱的
   顯著結果方向相反，很可能原始結果部分來自未修正的同日前視偏誤（見上方「跟原始研究的落差」）。
2. **部署邏輯的多空進場訊號沒有任何一格是「正確方向」的顯著**：12 個檢定裡通過 Holm 校正的 3 格全部
   是方向相反（多單訊號後續下跌、空單訊號後續上漲的顯著性),不是可用邊際。
3. **daily_trend gate 能降低虧損幅度,但不能讓策略轉為正報酬**——OOS 跟跨資產（ETH)都虧錢，gate 只是
   減少曝險/交易次數,不是找到真正有效的進場條件。
4. **以上全部是零成本數字**——真實成本會讓已經是負的 OOS/跨資產數字更差。

**建議：不建立 `strategy.py`。** 這個家族到目前為止，因子驗證跟原始研究的結論都指向同一個方向——沒有
找到可泛化、方向正確的邊際。若要繼續，下一步應該是回到因子分析階段換一個假設（例如不同的 RSI 週期/
門檛組合，或完全不同的動量定義),而不是在同一組已經測不出邊際的訊號上調整風控參數。

## 已知限制

- 只驗證了 BTC 決策 + ETH 穩健性,沒有測原始研究的第三個資產（TXFR1，台指期)——TW 期貨的交易時段
  跟 24/7 crypto 不同,套用同一套邏輯前需要 session-aware 處理（見
  `strategies/RESEARCH_METHODOLOGY.md`「非連續交易市場」的已知陷阱),本次不在範圍內。
- `mom_1D_10`/`long_entry`/`short_entry` 用了兩個獨立的 Holm 校正群組（連續因子 vs 事件訊號),因為
  這是兩個不同的決策形態（因子本身顯著性 vs 部署邏輯的訊號品質),不是同一輪多重比較——如果要更嚴格,
  可以把兩群一起校正,結論方向不會變（分開校正時 p 值已經是 1.0000 或方向相反,合併校正只會更不顯著）。
- 沒有做4的持有期/RSI 門檛橫掃——本報告驗證的是原始部署邏輯的參數，不是幫它找更好的參數。
